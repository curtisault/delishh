# delishh — the decision record

> Every ruling in force, dated, with what was rejected and why.
> Created 2026-09-28 by migrating the decision logs out of the four
> implementation plans (`delishh-redesign.md`, `meal-planner.md`,
> `meal-planner-expansion.md`, `installable.md`), which were dropped
> the same day: their phases were all done, and a plan whose only
> live content is its log is a log with a long preamble. The rulings
> are carried over verbatim where they still hold; a row a later
> ruling overturned is in `docs/decisions-archive.md`, with the date
> and the ruling that replaced it, and is never edited in place here.
> DS-01 (`docs/design-standard.md`) governs; where a ruling moved
> the standard, the standard carries the dated amendment and this
> record carries the reasoning.

**How to use this file.** A new ruling is a dated block appended at
the end, in the same three-column shape. A ruling that overturns an
earlier one moves the earlier row to the archive in the same commit,
so this file never holds two answers to one question. Rulings the
build enforces name their test; rulings a person holds say so.

## Ruled 2026-09-19, in the first five phases

Rulings the phases recorded in prose rather than in a table, kept
here as one row each.

| Decision | Ruling | Rejected alternatives |
|----------|--------|----------------------|
| A second renderer | **There will be no second renderer.** Print is an `@media print` stylesheet over the rendered document, with no print-specific JavaScript. A TypeScript print renderer beside the Elm one is the same failure that deleting `design-standard.html` ended — two copies with no rule about which wins — and print is where drift hurts most, because the sheet outlives the bug. The cost is that the site needs JavaScript to render at all, including before a print. Accepted | Prerendered recipe HTML (Revision 1's requirement, replaced by the Rev 2 rewrite's "printing is pure CSS") |
| Acid tokens by layer | `--shelf-*` are fills for browse surfaces; `--page-*` are marks for recipe surfaces; `--accent` is the actionable role and aliases `--shelf-act`. DS-01 §04's loud/quiet split is reviewable from the token name without reading the component | One set of four acids used on both layers |
| Ratio comments | Every contrast pair carries its **measured** ratio in a comment beside the hex, recomputed by `contrast_test.ts`; a token drawn on more than one ground names the background in the comment | A comment that can drift from its colour |
| The human voice above the fold | Instrument Serif is deliberately **not** preloaded: it appears in asides and at the foot of a recipe, never above the fold. Inter is | Preloading all four voices |
| The recipe page and `Doc` | **The recipe page does not wear `Doc`.** `Doc` frames prose documents — masthead, contents rail, numbered sections, citable `§N.M` marks. A recipe is a different object, and giving its blocks clause marks would be the "controlled document" register Revision 2 dropped. The site nav stays; the rail and search do not | Rendering a recipe as a numbered document |
| The prep card | `Prep` is **not a form**: it is supplemental and prints *alongside* any of the three, so it is a toggle in the picker, never a recipe's default. Derived entirely from what the recipe already carries — the tasks are the ingredients that have a preparation note | A fourth print template |
| Print token overrides | **Every print token override is `!important`.** A media query contributes no specificity, so the print palette competes with `theme.css` on selector weight and loses to `:root:not([data-theme='light'])`; without it a reader in dark mode prints a near-black page. The only fix that does not depend on which stylesheet the bundler places last | Matching the dark selector's shape (works only while `print.css` stays last) |

## Ruled 2026-09-21, at the print revision

| Decision | Ruling | Rejected alternatives |
|----------|--------|----------------------|
| What print is | **A designed page, not a styled printout.** The first print pass linearized the screen document and inherited its whitespace; the first real print run (the donuts booklet, 2026-09-21) spent four pages saying two pages of things. The reference is the source cards themselves — recovered, printed, and cooked from — and the traits worth carrying are ruled below, one each | Leaving print as the screen's shadow; Typst PDFs (still the escape hatch, still not needed — every fix below is CSS over the same document) |
| Ingredients on paper | **A row-aligned grid, not CSS multicolumn.** `columns: 2` balances by height, so wrapping names drift the two stacks and the hairline under each item pretends to be a table row that stops at the gutter. The grid pairs `qty · name · qty · name` in shared rows, so every rule really does run where it appears to. Reading order becomes across-then-down, which a shopping list tolerates and an aligned rule repays. A test forbids `columns:` coming back | Keeping multicolumn and dropping the hairlines (loses the scan lines that make quantities findable at a glance); single column (wastes the held half of the page) |
| The step line | **The cue moves to the step's number line in print** — right-aligned, the clock-and-tell where a standing reader looks first, body below. The source cards' step anatomy built from markup the steps already have. Screen keeps the cue beneath the body; print repositions, nothing is re-authored | A per-step `head:` field in the schema (new authoring burden duplicating the cue's job); leaving the cue buried under the body on paper |
| The duplex sheet | **The sheet form breaks before Watchpoints.** The blocks already split on the bench seam — Equipment/Ingredients/Steps are cook-side, Watchpoints/Rescues/Keeps/Note are reference — so the page break makes the sheet a duplex card: procedure on the front, recovery on the back, flippable with a wet hand | A separate back-page template (a second renderer); breaking before Rescues (a watchpoint is read *before* trouble, and belongs with the reference side, not the procedure) |
| The gauge strip | **New optional frontmatter: `gauges:`** — up to five hand-authored label · value (· note) pairs, the recipe's operating numbers. The single most useful trait of the source cards, and the one that cannot be derived: those numbers live in prose, and deriving them would be inference (§06). Hand-authored **printed content** is not hand-maintained metadata — a gauge is read at the bench and a wrong one fails the cook, which is the same force that keeps the steps honest. Rendered on screen *and* paper: two renderings of one file | Deriving gauges from cues/equipment (inference, banned); print-only rendering (content the screen hides); a closed gauge vocabulary (these are the recipe's own numbers, not a facet) |
| Facet chips on paper | **Dropped from print, all of them.** Slot, flavor, effort, cuisine — and dietary — are browse furniture: facets exist to *find* a recipe, and a printed sheet is already found. Ink goes to the gauge strip instead | Keeping dietary chips only (a verified flag matters when cooking for someone — but the ingredients are on the same page, and a half-kept chip row buys ambiguity with ink) |
| Density | **Page budgets enforced by design, not hoped for:** card = 1 page, sheet = 2 (one duplex leaf), booklet ≤ 4 full pages. The 11pt body floor stays — §09's standing reader is right — so the space comes out of what the floor does not protect: plate padding, block gaps, step padding, and the dead air between sections. A print rule states every side of a box it cares about, because `sheet.css`'s bare `section { margin-top }` governs any side a class leaves unnamed | Shrinking the body floor (breaks §09's own rule); leaving budgets as aspiration (the donuts booklet already showed what that produces) |
| Print QA target | **Print previews run against `deno task build` output, never the dev server.** The dev build overlays Elm's debugger badge fixed to the viewport corner, and fixed elements print on **every page**. Not a bug in the sheet; a rule about how to look at it | A print.css rule hiding the badge (styling a dev tool into the product stylesheet) |
| The plate's controls | The scale and the print form on the left, **COOK THIS at the right edge**, vertically centred against the two settings rows. Stacked beneath them the button read as a third setting and the right half of the plate sat empty. DOM order unchanged, so the tab order still runs scale → form → go; below the wrap the button returns to its own line. `.recipe-controls` does not print, as a box: an emptied flex row still contributes its gap | Leaving the button stacked under the settings |

## Ruled 2026-09-24, re-cutting the press dress

| Decision | Ruling | Rejected alternatives |
|----------|--------|----------------------|
| Which dress | **DK-06 EXTRUDED SLAB 45**, not DK-07 MACHINED BLOCK — a flat slab, its own edge, and one hard offset thrown down the 45° bearing. Every part of the slab is a flat fill offset behind another flat fill, which is what "depth comes from layering and overlap" means | Keeping the block (two tones are an axonometric, which is a drawing of how light falls); keeping it and going one-tone (a one-tone L reads as a drop shadow, not as stock) |

| The face | **One paper slab in both themes**, with both offsets carried toward `--ink`. A shadow is dark everywhere, and a slab is a slab — the `.tag-accent` argument applied to the one object in this design that is explicitly a piece of stock | A per-theme face (near-frost light, dark plate after dark): it made the control a different object in each theme, and every other token then had to bend around it |

## Ruled 2026-10-04, at the attribution

A recipe that came from somewhere gets to say so. Three recipes
arrived from one Houston restaurant, and the house rule that a title
names the **food** (Lime-Pepper Steak Fajitas, Warm Bean Dip, Roasted
Red Salsa) left nowhere for the restaurant's name to go. The name is
homage, not a facet: nobody browses by it, and it is never a word the
vocabulary holds.

| Decision | Ruling | Rejected alternatives |
|----------|--------|----------------------|
| The field | **`inspired: Lupe Tortilla`** in frontmatter, optional, one line of free text, kept exactly as typed. Rendered as **INSPIRED BY**, which is what people say and claims nothing false: the dish started from theirs and is yours now. Absent means **no attribution**, never "original"; the archive does not claim authorship of a dish any more than it claims a dietary flag | `after:` (the painter's convention, and it read as a time word beside LAST BATCH); `restaurant:` (true today, false the day a dish is after a grandmother or a cookbook); `homage to` (grand, for a bean dip); `as served at` (a lie — it is a copy from memory); a closed vocabulary (three recipes do not make a facet, and a filter over one restaurant is a filter that returns three things) |
| The title | **The title is the food, and the build enforces it.** A title containing the attribution's name, ignoring case, fails `deno task content` (`recipe_test.ts`): *Lupe Tortilla-Style Warm Bean Dip* is attributing twice, and *-style* and *copycat* are the sell register. The name lives in one place, so it can be right in one place | Leaving it to review (the existing *Wendy's-Style Frosty* was what review let through) |
| Where it sits | **Top right of the plate, in the serial row.** The row already carries the method mark and LAST BATCH on the left; the attribution is the row's last item, pushed to the far edge. Below 34rem the row wraps and it takes its own line under the date, left with everything else on the plate, still above the title — nothing hides and nothing clips (§12). The data voice, uppercase, the label dim and the name at weight 700 in ink, inside a 1.5px `--rule` box. **Prominent by shape and weight, not colour**: the page's one acid is the method's, and a name is not a quantity, an action or a process (§04). It is not an extruded slab, because a slab is a press and this does nothing | The chips row (a chip is a facet, outlined and hidden at print); an acid cameo (the plate already has one acid, on the method, and it earns it); bare text (a third serial fact, lost beside the date); the title itself |
| Print | **It prints**, in the same place, in ink. The chips do not print because they are for *finding*; the attribution is part of what the sheet *is*, like the title, and a printed sheet handed to a friend should say where the dish came from. Not on the footer: the footer is traceability, not credit | Hidden with the chips |
| Cook mode | **Not shown.** The cook head carries the title, the scale and the wake state — what a pair of wet hands needs. Homage is for reading | A line under the cook title (chrome the step anchors would then have to clear) |
| The shelf | **Searchable, and the row does not draw it** (`ShelfTests`). The name rides on the index summary and into `matchesQuery`'s haystack, so typing *lupe* finds all three. A row is method, title, flavour, times, keeps, and a sixth column is a row that wraps on a phone. *The fifth-path half of this row was overturned the same day, below* | A row tag (clutter at three recipes) |
| The Note | **The story goes in the Note, in the cook's words.** The field is the fact — *this dish is after that place* — and the Note is why: the booth, the sizzling platter, what the copy gets wrong. The field is never read out of the Note; picking a name from a paragraph is inference (§12) | Deriving the tag from a Note that names a restaurant |
| The word rules | **The name is exempt.** A restaurant may be called *The Best Little Taco Stand Ever*, and the checker does not read a proper noun. The title rule above is the only check it gets | Running `WORD_RULES` over it |
| The existing case | **`wendys-style-frosty` keeps its slug.** The slug is the recipe's identity, rides in the shopping list's and the planner's stores on every reader's device, and a renamed slug is a planned week pointing at *no such recipe*. The title moves to the food — *Chocolate Malt Frosty* — with `inspired: Wendy's` | Renaming the slug (breaks two stores on every reader's device) |

## Open — deferred, not decided

Carried out of the plans' *Open items*. Each is a decision **not to
decide yet**, with the condition that would reopen it. Strike a line
when it is ruled and the ruling is dated above.

- **Typst.** If CSS print cannot hit the layout quality wanted for `booklet` (running headers, precise page control), revisit Typst-generated PDFs as a *download* option layered on top. Not a replacement for CSS print.
- **Photos at print.** Halftone-at-build (preprocessed asset) versus CSS-filter-at-print. No recipe names a photo yet, so it is a sentence, not work.
- **The freezer label strip.** The source cards end with a cut-here strip — dish name, frozen-on, use-by, reheat line. Wanting one is a property of the *recipe* and no schema field says so; deriving it from the Keeps prose would be inference. If it comes, it is a picker toggle like the prep card, and the dates stay blank for a pen.
- **The week onto the list.** Every planned recipe onto the shopping list in one press — the two stores already speak the same slug. Not built until the planner has been used for a few weeks; whether the list wants *this week's* recipes or the ones not yet bought for is answerable only by use, and several recipes a day makes it more attractive and no better defined.
- **A dated week.** If "which week is this picture for" is asked, the answer is a caption the *sender* types onto the picture, never a date the archive computes.
- **Own meals that later become recipes.** The plan holds what was typed and should not know. A future entry-field nicety could say "the archive now has this" and offer the swap, on the reader's press.
- **The picture in the lit palette regardless of theme.** If dark-mode readers want a paper-coloured card, the route is a token read against a `data-theme="light"` document the drawing code owns, not a second palette in `boot.js`.
- **A label the vocabulary lacks.** *Brunch*, *tea*. A new word is one line in `vocabulary.ts`, one in `Plan.slots`, and a test that fails if only one moves. Widened only when a real week wants it.
- **Two-line meals in a five-entry day.** The height budget's worst case is thirty-five wrapped entries; if own meals turn out to be sentences, the drawing wants a per-entry line cap before a third type step.
- **A reload banner.** If the no-prompt ruling leaves readers on a stale build in practice, the route is one incoming port (`updateReady`), one sentence in the site bar, one press. It would be the shell's second subscription, and it should earn that.
- **Step stamps across a reload.** An installed app makes an accidental close slightly more likely; if observed, the answer is a port and a storage key, not anything in the worker.
- **A store listing.** Android can wrap an installed web app as a Trusted Web Activity with no change to this code. Not planned; noted so the option is not forgotten.
- **The corpus outgrowing the pre-cache.** At a megabyte the whole-archive ruling is obviously right; at fifty it is not, and the line is a judgement to make when the size is real.
- **A `tex-mex` cuisine.** If the recipe review keeps wanting a word `american` stretches to cover, that is the case for widening the list, not for stretching `mexican`.
- **The restaurant list in the URL.** Each browser has its own list. If "send me your list" is asked, the route is the list encoded in the address the way the scale rides in cook mode's — never a server.
- **A `how` on a restaurant.** Delivery, pickup, go out — a facet to spin over. Widened only when a real Friday wants "delivery only"; until then a name is the whole entry.
- **The plan saying *from a restaurant*.** The week holds the name a spin placed and nothing about where it came from. If the picture should say it, that is a third `Meal` variant and a mark on the drawing, and the ruling is that the plan does not know until someone needs it to.
- **The attribution on the shelf row.** Revisit if readers scan the shelf for a place rather than a dish; until then the search finds it.
- **A link on the attribution.** The field carries a name and no URL. A restaurant's address in the archive is a thing that rots; if wanted, it is a second optional field, never a parse of the name.
